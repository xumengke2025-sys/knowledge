# 从资料构建行业专家

目标是让专家掌握行业专业知识，正确、有逻辑地回答实际问题。采用专业知识、简洁分析指引和已有数据接口，不把工作演变成复杂的专家生成引擎、逐回答审查系统或固定输出模板。可以综合访谈经验，不能移植受访者的真实身份、资历和机构背书。

## 对齐系统和材料

确认资料目录、目标系统、现有专家配置标准、知识库方式、工具注册及发布入口，并区分本次交付是资料包、离线适配、运行服务导入还是专家发布。复用已有解析、OCR、检索和业务数据接口；只有确实缺少所需能力时才补充插件。用户仅要求准备时，完成可复核的数据包与导入验证，不把生产发布当作已获授权。

在 firmbuddy 工作时读取 [references/firmbuddy.md](references/firmbuddy.md)，按当前代码与运行服务核对接口，不直接沿用旧端口、专家 ID 或硬编码路径。

从归集开始维护六层映射：专家职责与内置基础 → 插件实际工具 → 可调用的研究技能 → 来源文档及版本 → 知识装备与 Loadout → 试题与验收记录。每份材料至少记录目标行业、用途、来源类型、阅读状态、定位、哈希和导入去向；目标运行 ID 由正式接口创建后回填，不预造 KB 引用。

插件负责执行与检索能力；技能负责可复用的研究步骤；知识库保存事实与原文；装备选择专家可访问的确定版本知识。这些不能互相替代。若系统没有通用技能加载器，将工作规范挂到已有合适的只读工具，或提供最小插件适配；不得声称放入 SKILL.md 就已被专家加载。工具白名单使用实际注册名称，知识入库不自动授予权限。

## 逐文件整理

可用 `scripts/inventory_sources.py SOURCE --output MANIFEST` 盘点文件，用户排除照片时加 `--exclude-images`。脚本只盘点与检测完全重复，不解析语义或解压归档。

维护路径、哈希、类型、处理状态和失败原因。完全重复文件共用解析结果；修订稿、综合报告保留来源关系，不能算独立共识。检查压缩包成员，补入外部目录不存在的材料。

提取正文、表格、幻灯片及有内容的备注，长文完整分块读取并保留页码、段落或表格定位。扫描文件按需 OCR，关键数字和专业符号回看原页。图片是否处理服从用户范围；OCR 无文字不等于理解图像。录音可先利用已有文字记录，但要说明是否独立转写或复听原录音。

解析结果稳定后再派发语义整理。增量任务用输入哈希判断需要重读的分块，避免首次快照漏掉后补材料。分别记录已读、重复、用途排除、失败和尚待处理，不能把“已解析”写成“已理解”。

## 整理专业知识

行业边界和专家范围由内容决定。完整行业材料可形成综合专家；单个项目评价或零散案例只支持案例知识或较窄范围，不按人数、文件数量凑专家。

优先整理概念原理、技术路线、产业链、应用、商业模式和经验。重要观点保留来源、时点和条件，区分原文、受访者意见及整理者推导。原文有错或矛盾时说明并修正，不因资料权威或重复出现就照搬。稳定知识与市场、政策、企业等动态事实分开。

专业基础写成专家直接可用的知识说明，详细材料放入检索库。证据条目能回到原文和上下文，直接引文核查一致性，模型改写抽查是否改变范围或口径。不必对全部条目重复调用模型审查。行政信息和无关个人材料不纳入行业知识。

## 公开研究与学术深度

资料涉及论文、专利或产业技术时，读取 [references/research-evidence.md](references/research-evidence.md)。围绕技术原理、路线权衡、关键指标、实验条件、失效机制和放大瓶颈整理专业知识，避免以公司数量或论文标题数量代替深度。

将论文书目、摘要阅读、正文局部阅读和全文研究分开；只获取DOI或下载正文不算完成研究。区分综述、原始实验、仿真、数据集与预印本。保留方法、样本、基线、单位、测试条件、结果和外推限制；无法取得全文时交付实际可读层级和待补问题，仍可继续独立模块。

## 公司技术路线与特色识别

构建的行业专家应能将专业知识用于具体公司：依据资料判断技术路线、产业链环节、产品特点及可能的差异化，允许多路线并存或证据不足。整理材料时保留公司名称、产品或项目、技术描述、来源时点与上下文，区分已推出产品、研发探索和访谈评价，不把提及某条路线直接等同于公司采用该路线。

先检查目标系统已有的企业搜索、画像、专利和产品资料检索能力。若只能返回工商或专利列表，缺少公司技术证据检索，则按需补充插件，将明确提及目标公司的原文及出处提供给专家，配合已有接口核查当前情况；技术判断沿用专家正常推导，不另建自动认证或多层审查引擎。新工具同步加入专家白名单与构建脚本。

核查全称、简称及历史主体关联；同名、分公司、竞品、客户和供应商的技术不能混归。专利标题、经营范围和行业分类仅是线索；产品覆盖广不证明“全栈自主”，专利数量也不证明技术领先。区分有证据的产品特点与尚待比较验证的优势，“独有、领先、自主程度”需要产品原文、技术指标或同口径竞品证据。历史描述标注时点，未命中或接口失败不等于企业没有技术。

用实际公司问题验证是否调用工具、正确归属证据并据此说明技术路线与特色；另检查无证据或主体歧义时的处理。分别记录工具接入、检索正确性和专业回答质量：若回答仍有证据不足的优越性表述，修正后复测并如实披露残余问题，不能把工具测试通过写成专家判断已可靠。

## 创建、验证、发布

按现有标准填写专业范围、内置知识、简洁方法和工具白名单。方法帮助解释原因和比较条件，允许按问题自然回答。用户未要求训练模型时，不把知识库构建称作模型参数训练。

用少量实际问题检查知识准确性、推导和结论依据，覆盖概念解释、条件分析、原文核查和数据查询。针对发现修正，不为每道题累积通用限制或无限追求零错误。

资料包交付应含导入清单、版本/哈希、插件与技能调用映射、装备类型及槽位、专家配置、试题、覆盖与失败记录。增量导入按稳定逻辑键和内容哈希避免重复；文档更新追加版本，装备绑定确定 DocumentVersion，Loadout 使用当前修订的 CAS，不自动将已装备旧版本漂移到最新版。

分开记录四类验证：数据与引用完整；插件/技能实际可调用；知识文档与装备可检索且能还原引用；真实专家回答的技术准确性与条件推导。离线结构校验不能写成运行时导入成功，检索命中不能写成专业回答已合格。源库旧数据与本次核验新增数据分别标识。

在用户授权范围内通过正式入口发布，更新前备份。按唯一身份或名称判断创建/更新，避免重复专家。发布后读回分类、配置和工具权限，再执行实际对话验证身份、原文读取及数据接口。注册成功不等于查询成功，生成配置不等于已发布。

交付说明已发布专家和入口、知识范围、实际测试及材料缺口。保留构建脚本和发布记录，新增文件只处理变化部分。
